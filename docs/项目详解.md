# Music 音乐平台 · 项目详解

一个基于 Spring Boot 的音乐分享与互动平台，支持音乐上传/播放、用户注册激活、点赞、评论、热度排行、**实时通知推送**、消息队列推荐、系统规则配置等功能。

> 本文档面向想快速理解整体架构与各功能模块实现的开发者。仓库根目录另有一份英文 `README.md`（侧重环境搭建与 curl 示例），可配合阅读。

## 四、分模块详解

### 1. 用户模块（`/user`）

负责账号全生命周期：注册 → 邮件激活 → 登录 → 信息管理。

**接口**

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| POST | `/user/register` | 注册（`RegisterCmd`：name/password/age/interests/email） |
| PUT | `/user/activate?name=&code=` | 邮箱激活码校验 |
| GET | `/user/login?name=&password=` | 登录 |
| PUT | `/user/update?userId=&interests=` | 更新兴趣 |
| GET | `/user/info?name=` / `/user/id?id=` | 查询用户 |
| GET | `/user/query-all?start=&pageSize=` | 分页列出用户 |
| POST/PUT/DELETE | `/user/add` `/user/modify` `/user/delete` | 后台增改删 |

**核心流程**

- **注册**：校验用户名唯一 → 密码 `MD5Util.md5()` 加密、状态置 `INIT` → 落库 → 生成 6 位激活码（`ActivateUtil`）→ 套用邮件模板（`MusicConstant.EMAIL_HTML` 的 `{{code}}`）发送激活邮件 → 激活码写入 Redis `user_activate:{name}`（**TTL 5 分钟**）→ 记录用户兴趣标签。
- **激活**：从 Redis 取激活码比对，通过则状态改为 `NORMAL`。已激活直接返回，`ABNORMAL` 拒绝。
- **登录**：校验状态与 MD5 密码 → 生成 `UserToken` 存 Redis `user_token:{userId}`（**TTL 60 分钟**）。

**Redis 用途**

| Key | 内容 | TTL |
| --- | --- | --- |
| `user_name:{name}` / `user_id:{id}` | 用户对象缓存 | 永久（改删时清除） |
| `user_token:{userId}` | 登录令牌 | 60 分钟 |
| `user_activate:{name}` | 激活码 | 5 分钟 |

**用户状态枚举**（`UserStatusEnum`）：`INIT`（待激活）→ `NORMAL`（正常）；`ABNORMAL`（禁用，无法激活/登录）。

**异常**：`UserDuplicatedRegisterException`、`UserNotExistException`、`UserPasswordErrorException`、`UserFailActivatedException`、`UserNotAllowedException`、`EmailFailActivatedException`。

> 安全提示：密码使用无盐 MD5，仅适合演示；生产环境建议改为 BCrypt 等加盐哈希。

### 2. 音乐核心模块（`/music`）

音乐记录的增删改查，以及音频/封面文件上传到 MinIO。

**接口**

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| POST | `/music/upload/audio` | 上传音频到 MinIO，返回访问 URL |
| POST | `/music/upload/image` | 上传封面图片到 MinIO |
| POST | `/music/add` | 新建音乐（`MusicCmd`） |
| PUT | `/music/modify` | 修改音乐 |
| DELETE | `/music/delete` | 删除音乐 |
| GET | `/music/id?id=` | 按 ID 查询 |
| GET | `/music/title?title=` | 按标题查询 |
| GET | `/music/query-all?start=&pageSize=` | 分页（按发布时间倒序） |

**文件上传流程**：`MinioUtil` 在应用启动时自动建桶并设置公共读策略；上传时对象名为 `{folder}/{uuid}/{原文件名}`（UUID 防重名、防路径穿越），返回完整可直连 URL。

**查询缓存**：按 id / title 查询走 Redis 缓存（`music_id:{id}`、`music_title:{title}`），未命中回源 DB 再回填；修改/删除时清除两个 key。分页查询不缓存。

**实体字段**：`title`、`content`(歌词)、`author`、`tags`、`pictureUrl`、`audioUrl`、`publishTime`；`MusicVO` 额外带 `hotScore`（来自排行榜）。

**联动**：新增音乐会向排行榜初始化记录，并通过 Kafka 投递上新事件（见模块 8）。

---

### 3. 点赞模块（`/music-like`）

纯 Redis 实现的双向点赞关系。

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| POST | `/music-like/add` | 点赞 |
| PUT | `/music-like/cancel` | 取消点赞 |
| GET | `/music-like/get-music-like?musicId=` | 该音乐的点赞用户列表 |
| GET | `/music-like/get-user-like?userId=` | 该用户点赞过的音乐列表 |

**存储**：Redis List，双向维护 `music_like:{musicId}`（点赞用户）与 `user_like:{userId}`（点赞音乐）。点赞时两边 `rightPush`，取消时两边 `remove`，并同步更新热度分（`+1.0 / -1.0`）。

---

### 4. 热度排行榜模块（`/music-rank`）

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| GET | `/music-rank/topN?n=` | 取热度前 N 的音乐 |

**存储**：Redis Sorted Set，单 key `music_rank`（member=musicId，score=热度）。

**积分规则**（`MusicConstant`）：点赞 `LIKE_SCORE=1.0`、评论 `COMMENT_SCORE=2.0`。查询时 `reverseRange` 取降序 ID，再用 `MusicMapper.queryByIds` 批量回表拿完整信息。

---

### 5. 评论模块（`/comment`）

支持无限层级的树形评论（`parent_id` 关联，`leaf` 标记是否叶子节点）。

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| POST | `/comment/add` | 发表评论 / 回复 |
| GET | `/comment/query?musicId=` | 查询某音乐的全部评论 |
| GET | `/comment/get?id=` | 按 ID 查单条评论（供通知跳转定位使用） |
| PUT | `/comment/modify?id=&content=` | 修改评论 |
| DELETE | `/comment/delete?id=` | 删除评论（级联删子孙） |

**要点**：

- 发表评论 → 音乐热度 `+COMMENT_SCORE`。若是回复（`parentId≠0`），把父评论标记为非叶子，并**给父评论作者生成一条通知**。
- 删除评论用 BFS 队列级联删除所有子孙评论，并按删除数量相应扣减热度分。
- 查询时后端 `fillUserNames` 批量填充评论者昵称（带缓存，避免 N+1 查询）。

---

### 6. 通知模块（`/notification`）★ 含实时推送

站内通知，并通过 **SSE 实现无刷新实时到达**。

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| GET | `/notification/query?to=&start=&size=` | 分页查询某用户收到的通知 |
| GET | `/notification/subscribe?to=` | **SSE 订阅实时通知流**（`text/event-stream`） |
| DELETE | `/notification/delete?id=` | 删除通知 |

**实时推送设计**

- `NotificationEmitterRegistry`（`@Component`）按用户维护 `SseEmitter` 连接池（`Map<userId, List<SseEmitter>>`，支持一个用户多标签页），连接超时 30 分钟，异常/超时自动清理，浏览器 `EventSource` 断线自动重连。
- `NotificationServiceImpl.addNotification` 写库后，立即通过 registry 向接收者推送 `notification` 事件；mapper 用 `useGeneratedKeys` 回填自增 id，保证推送载荷带 id 供前端去重/标记未读。
- **前端行为**：
  - `music.html` 建立 SSE 连接，收到推送即重算铃铛未读角标（基于 `localStorage` 的已读游标 `notifRead_{userId}`），无需刷新。
  - `notification.html` 收到推送后把新通知即时插入列表顶部并高亮为未读。
  - 点击通知（`targetType=COMMENT`）跳转至 `music.html?commentId=`，页面据评论 id 反查所属音乐 → 打开详情 → 定位并高亮对应评论（`scrollIntoView` + 闪烁动画）。

### 8. 消息队列与推荐（Kafka）

- **MusicProducer**：新音乐上架时向 topic `add-music` 投递 musicId。
- **MusicConsumer**（消费组 `test-group`，监听 `add-music`）：
  1. 更新排行榜记录；
  2. 按音乐标签从 `MusicInterestsRepository`（Redis Set `recommend_by_music_tag:{tag}`，维护"对某标签感兴趣的用户集合"）检索目标用户；
  3. 用 `MusicConstant.RECOMMEND_EMAIL_HTML` 模板向这些用户发送上新推荐邮件。
- **TestProducer / TestConsumer**：`test-topic` 上的收发测试样例（配套 `/test-message` 接口）。

> 该模块把"上新通知/推荐"从主流程异步解耦，避免上传接口被邮件发送阻塞。

### 9. 系统配置模块（`/systemConfig`）

以 `code-value` 形式动态维护业务规则（如分页大小等），避免硬编码。

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| POST | `/systemConfig/add` | 新增配置（`SystemConfigCmd`） |
| GET | `/systemConfig/modify?code=&value=` | 修改配置值 |
| GET | `/systemConfig/query?code=` | 查询单条 |
| GET | `/systemConfig/queryAll` | 查询全部 |
| DELETE | `/systemConfig/delete?code=` | 删除 |

`code` 唯一，推荐点分命名（如 `rule.search.pageSize`）。对应可视化管理页 `rule-config.html`。

## 七、典型调用链示例

**发表回复触发实时通知**

```
POST /comment/add (parentId≠0)
  └ CommentServiceImpl.addComment
      ├ commentMapper.addComment            # 落库
      ├ musicRankRepository.updateScore(+2) # 热度
      └ notificationService.addNotification
          ├ notificationMapper.addNotification (回填 id)
          └ NotificationEmitterRegistry.send(toUserId, VO)  # SSE 推送
                └ 接收者浏览器 EventSource 收到 → 角标+1 / 列表置顶（无刷新）
```

**查询热榜**

```
GET /music-rank/topN?n=10
  └ ZREVRANGE music_rank 0 9 → [musicId...] → MusicMapper.queryByIds → MultiMusicVO
```

**新音乐上新推荐**

```
POST /music/add → Kafka(add-music, musicId)
  └ MusicConsumer 消费
      ├ 排行榜登记
      └ 按 tags 命中兴趣用户 → 逐个发送推荐邮件
```
